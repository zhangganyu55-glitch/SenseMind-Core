# SenseMind Design System · UI 2.0

> 版本 1.0 ｜ 2026-11-03 ｜ 适用：Android Companion + Mac Care Center
> 设计方向：**Warm Minimalism** · Technology with Empathy

---

## 0. 两张参考图怎么用

| 参考 | 借什么 | 不借什么 |
|---|---|---|
| **grace.**（手机） | 版式节奏：大号问候语 + 柔和圆角卡 + 充足留白 + 底部导航中央凸起主操作；卡片的「图标圆块 + 标题 + 说明 + 箭头」结构 | 粉色调、装饰性衬线体品牌字、纪念日/信件这类社交内容结构 |
| **Guardian Oasis**（桌面） | 信息架构：左侧家人列表 → 中央「今天」摘要 + 人物卡 → 右侧提醒；顶部品牌与家庭切换；克制的绿色主按钮 | 偏冷的青绿、过多的小徽章、医疗器械感的分区线 |

**配色以任务书给定的 token 为准**（绿系），不采用参考图里的粉色。参考图解决的是**版式、层次、温度感**，不是色相。

一句话：**Guardian Oasis 的骨架 + grace. 的呼吸感 + 任务书的绿色。**

## 1. 设计原则

1. **一屏只说一件事**：首页第一屏回答「家人今天怎么样」，不回答「系统跑了多少条数据」。
2. **状态先于数值**：先给「一切正常 / 需要留意 / 请尽快查看」，再给心率和血氧。
3. **技术隐于幕后**：BLE、CRC、Token、JSON、Evidence ID 全部下沉到诊断模式。
4. **空就是空**：没有数据显示「尚未收到」，绝不显示 0。
5. **克制的情感**：可以有问候语和温度，但不能用颜色和动效制造焦虑。

## 2. 颜色 Token

### 2.1 基础色（任务书给定，不得更改）

| Token | HEX | 用途 |
|---|---|---|
| `bg` | `#F5F6F2` | 页面背景 |
| `surface` | `#FFFFFF` | 卡片 |
| `primary` | `#326F68` | 品牌主色 / 主按钮 / 选中态 |
| `primarySoft` | `#E7F0EC` | 主色浅底 / 图标圆块 / 选中背景 |
| `textPrimary` | `#252F2C` | 主文字 |
| `border` | `#DCE3DF` | 边框 / 分隔线 |
| `success` | `#4F9277` | 正常 |
| `warning` | `#C28A43` | 需要留意 |
| `danger` | `#BD625B` | 高优先级 |

### 2.2 扩展色（本设计补充，需评审确认）

| Token | HEX | 用途 | 说明 |
|---|---|---|---|
| `textSecondary` | `#5C6B66` | 次要文字、说明 | `textPrimary` 的次级，对比度 ≥ 4.5:1 |
| `textTertiary` | `#8A9691` | 时间戳、单位、占位 | 仅用于 ≥ 13sp 的辅助信息 |
| `surfaceMuted` | `#FAFBF9` | 次级卡片 / 表格行底 | 比 `surface` 略灰，用于分区 |
| `dangerSoft` | `#F7EBE9` | 高危事件卡底色 | `danger` 的 10% 底 |
| `warningSoft` | `#F8F1E6` | 留意事件卡底色 | `warning` 的 10% 底 |
| `successSoft` | `#EAF3EF` | 正常态底 | `success` 的 10% 底 |
| `overlay` | `rgba(37,47,44,0.32)` | 弹层遮罩 | |

### 2.3 用色规则

- **主色面积不超过一屏的 10%**。绿色是强调，不是底色。
- 状态色**只用于状态**：`success/warning/danger` 不得用于装饰。
- **禁止**：渐变背景、发光边框、霓虹色、纯黑 `#000`、纯白文字压色块。
- 事件卡按等级用 `*Soft` 底 + 左侧 3px 色条，不用满屏着色。

## 3. 字体与字阶

### 3.1 字体选择

| 场景 | 字体 | 说明 |
|---|---|---|
| 中文正文 | 系统默认（PingFang SC / 思源黑体） | 不引入字体包，控制 APK 体积 |
| 数字与大标题 | 系统 Sans，**weight 600** | 用字重建立层次，不靠花体 |
| 英文品牌字 | 系统 Serif（仅 `SenseMind` 标识与「早上好」可选用） | 可选；若打包体积敏感则统一用 Sans |

> 参考图 grace. 的衬线大标题很有气质，但中文衬线在 Android 上需要打包 3–5 MB 字体。**建议：中文全部用黑体，只在数字（心率、血氧）上用等宽数字特性 `tnum`，保证跳动时不抖。**

### 3.2 字阶

| Token | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| `display` | 34 / 40 | 600 | 问候语「早上好，李阿姨」 |
| `title1` | 24 / 32 | 600 | 页面主标题 |
| `title2` | 20 / 28 | 600 | 卡片组标题 |
| `title3` | 17 / 24 | 500 | 卡片标题 |
| `body` | 15 / 22 | 400 | 正文 |
| `bodyStrong` | 15 / 22 | 500 | 强调正文 |
| `caption` | 13 / 18 | 400 | 说明、时间 |
| `micro` | 11 / 14 | 500 | 徽标、单位（**不用等宽**） |

**数值专用**：`metric-lg` 40/44 weight 600 `tnum`；`metric-md` 28/32 weight 600 `tnum`；`metric-sm` 20/24 weight 600 `tnum`。

> 现有 `labelSmall` 是 Monospace + 1sp 字距，视觉上非常「工程」。UI 2.0 把它取消，只在诊断模式保留等宽。

## 4. 间距 · 圆角 · 阴影 · 动效

### 4.1 间距（8pt 栅格，允许 4pt 半档）

| Token | 值 | 用途 |
|---|---|---|
| `s1` | 4 | 图标与文字 |
| `s2` | 8 | 卡内行距 |
| `s3` | 12 | 卡片间距（小） |
| `s4` | 16 | 卡片间距（标准） |
| `s5` | 20 | 页面左右边距（移动端） |
| `s6` | 24 | 区块间距 |
| `s7` | 32 | 大区块间距 |
| `s8` | 40 | 首屏顶部留白 |

### 4.2 圆角

| Token | 值 | 用途 |
|---|---|---|
| `r-sm` | 8 | 徽标、输入框 |
| `r-md` | 12 | 小卡片、按钮 |
| `r-lg` | 16 | 标准卡片 |
| `r-xl` | 20 | 大卡片、人物卡 |
| `r-full` | 999 | 图标圆块、头像、胶囊 |

### 4.3 阴影

| Token | 值 | 用途 |
|---|---|---|
| `shadow-1` | `0 1px 2px rgba(37,47,44,0.04)` | 卡片默认 |
| `shadow-2` | `0 4px 16px rgba(37,47,44,0.06)` | 悬浮卡、底部导航 |
| `shadow-3` | `0 8px 32px rgba(37,47,44,0.10)` | 弹层、抽屉 |

**不用**发光、不用彩色阴影。

### 4.4 动效

- 时长：**150–250ms**；缓动 `cubic-bezier(0.2, 0, 0.2, 1)`
- 允许：页面切换淡入 + 轻微上移（8px）、卡片按下缩放 0.98、数字变化淡入
- **禁止**：持续闪烁、呼吸灯、循环脉冲、连续骨架屏超过 1.5s
- 告警状态**不用闪烁**表达，用颜色 + 图标 + 文案

## 5. 组件规范

> 两端视觉一致、业务语义一致；实现各自技术栈（Compose / 原生 HTML+CSS）。

### 5.1 StatusCard（今日状态卡）

首页第一块，回答「今天怎么样」。

```
┌──────────────────────────────────┐
│  ● 一切正常                       │  ← 状态点 + 状态词（success/warning/danger）
│                                   │
│  今天 6 次测量，数据完整           │  ← 一句话摘要（body）
│  最近更新 09:41                   │  ← caption，textTertiary
└──────────────────────────────────┘
```

- 背景：`surface`；左侧 4px 竖条用状态色
- 状态词只有三档：**一切正常 / 需要留意 / 请尽快查看**
- 无数据时：状态词「尚未收到数据」，点用 `textTertiary`，摘要说明最后尝试时间

### 5.2 MetricCard（指标卡）

```
┌────────────┐
│ 心率        │  ← caption
│ 72          │  ← metric-md + unit
│ 次/分       │
│ 09:41 · 良好│  ← micro，含时效与质量
└────────────┘
```

- 2 列或 3 列网格，间距 `s3`
- 数值缺失：显示 `—`，副标题写「尚未收到」；**不显示 0**
- 数据过期（`stale=true`）：数值降到 `textSecondary`，右上角加 `DataFreshnessLabel`

### 5.3 TrendChart（趋势图）

- 高度 180–220，无网格背景（或用 `border` 极浅横向 3 条）
- 线宽 2px，主色 `primary`；面积填充 `primarySoft` 20%
- 断点用**断开**表示（不插值），不要连成一条假曲线
- X 轴只标 3–4 个时间点；Y 轴不标刻度线，只标上下限
- 空状态：居中显示「这段时间还没有数据」

### 5.4 EventCard（事件卡）

```
┌──────────────────────────────────┐
│▎ 心率偏高                 待确认  │  ← 左侧 3px 等级色条 + 名称 + 状态徽标
│  10:12 · 持续 4 分钟              │
│  睡眠中静息心率高于个人基线 18%    │  ← 关注原因（人话）
│  ⏳ 正在进一步分析                │  ← 调查状态
└──────────────────────────────────┘
```

- 徽标两套，不能混：**确认状态**（待确认 / 我已了解）与**调查状态**（持续观察中 / 正在进一步分析 / 分析已完成 / 当前证据不足）
- 点整卡进详情

### 5.5 EventTimeline（事件详情时间线）

竖向时间线，节点 = 事件发生的各个阶段：

```
● 10:12  检测到心率偏高
│
● 10:13  系统开始进一步分析
│
● 10:15  分析完成，证据 4 条
│
○ 10:20  家属已了解          ← 空心点表示人工动作
```

### 5.6 AgentInsightCard（知微观察）

```
┌──────────────────────────────────┐
│ ✦ 知微观察              分析已完成 │
│                                   │
│ 本次观察：夜间静息心率连续 3 晚偏高 │
│ 调查依据：3 晚 · 12 条证据          │
│ 结论：与近期睡眠时长减少相关        │
│ 不确定性：样本仅 3 晚，不能排除其他 │
│                    [查看完整分析]  │
└──────────────────────────────────┘
```

- 图标 `✦` 用 `primary`，不要用机器人/大脑这类具象图标
- 「不确定性」一栏**必须有**，无内容写「本次样本量较小」
- 右下角次级按钮进入详情，详情里才出现 Evidence ID

### 5.7 EvidencePanel（证据面板）

只在事件详情与诊断里出现。

| 列 | 内容 |
|---|---|
| 来源 | 心率 / 血氧 / 加速度 / 雷达 |
| 值 | 数值 + 单位；缺失显示 `—` |
| 质量 | 良好 / 一般 / 不足 |
| 模式 | `LIVE` / `REPLAY` / `SYNTHETIC` 徽标 |
| 时间 | 本地时间 + 时钟不确定度（有则显示） |

**模式徽标必须逐条保留**，这是数据可信度的底线。

### 5.8 DeviceStatusCard（设备卡）

- 三态：**已连接 / 最近连接 / 未连接**
- 「已连接」只代表链路通，**不等于健康正常** —— 副标题固定为「数据更新于 xx」
- 电量：后端没有就**不显示这一行**，不做占位

### 5.9 DataFreshnessLabel（时效标签）

`刚刚` / `3 分钟前` / `1 小时前` / `数据已过期` / `尚未收到数据`

- < 2 分钟：`textTertiary`
- 2–30 分钟：`textSecondary`
- > 30 分钟或 `stale`：`warning` + 「数据已过期」

### 5.10 EmptyState（空态）

必须包含三件事：**说明为什么空 + 下一步做什么 + 一个可点的动作**

```
     ◌
 还没有收到数据
 请确认设备已开机并在蓝牙范围内
     [ 重新连接 ]
```

禁止只放一个「暂无数据」。

### 6.2 趋势详情

```
┌─────────────────────────────────┐
│  ‹   心率趋势                    │
│                                 │
│  [今天] [近 7 天] [近 30 天]     │  ← 分段控件，胶囊
│                                 │
│  平均 74    最高 96    最低 61   │  ← 三指标一行
│                                 │
│  ┌─────────────────────────────┐│
│  │        ╱╲    ╱╲             ││  TrendChart
│  │   ╱╲  ╱  ╲  ╱  ╲            ││
│  └─────────────────────────────┘│

│  ⓘ 本时段有 2 段数据缺失（灰色） │  ← 数据质量说明，必须显示

```

### 6.3 事件详情（四段式）

```
┌─────────────────────────────────┐
│  ‹   心率偏高                    │
│      10:12 · 持续 4 分钟          │
│                                 │
│  ① 发生了什么                    │
│  睡眠中静息心率高于个人基线 18%    │
│                                 │
│  ② 系统观察到了什么              │
│  ● 10:12 检测到心率偏高          │
│  ● 10:13 开始进一步分析          │
│  ● 10:15 分析完成               │
│                                 │
│  ③ 知微的调查结果                │
│  ┌───────────────────────────┐  │
│  │ 结论 / 证据 4 条 / 不确定性  │  │
│  └───────────────────────────┘  │
│                                 │
│  ④ 我可以做什么                  │
│  [ 我已了解 ]      [ 继续观察 ]  │  ← 主按钮仍是「我已了解」
└─────────────────────────────────┘
```

**「我已了解」不得改成「已处理」「已解决」** —— ACK 只表示人看过了。

### 6.4 家庭与设备

- 家人列表：头像圆块 + 名字 + 今日状态点 + 设备在线状态（两级信息分开）
- 设备卡：三态 + 数据更新时间 + `[重新连接]`
- 隐私 / 授权 / 通知：标准表单页
- 底部入口：**高级诊断**（BLE 日志、CRC、上传状态、Agent 工具调用）—— 折叠，不在主界面出现

## 8. 状态矩阵（任务书第七节，10 种情况）

| # | 状态 | 状态词 | 颜色 | 数值区 | 必须出现的信息 |
|---|---|---|---|---|---|
| 1 | 正常 | 一切正常 | success | 数值 | 更新时间 |
| 2 | 数据缺失 | 尚未收到数据 | textTertiary | `—` | 最后尝试时间 |
| 3 | 数据延迟 | 数据已过期 | warning | 数值降到次级色 | 实际更新时间 |
| 4 | 设备断开 | 设备未连接 | textTertiary | `—` | [重新连接] |
| 5 | 传感器异常 | 传感器读数异常 | warning | 异常项 `—` | 哪一项异常 |
| 6 | 数据质量不足 | 数据质量不足 | warning | 保留数值 | 「仅供参考，不作为判断依据」 |
| 7 | 调查中 | 正在进一步分析 | primary | 正常显示 | 预计时间（有则显示） |
| 8 | 调查失败 | 分析未能完成 | warning | 正常显示 | [重试] + 失败原因的人话 |
| 9 | 证据不足 | 当前证据不足 | textSecondary | 正常显示 | 「样本量不足，继续观察」 |
| 10 | 已确认 | 我已了解 | textSecondary | 正常显示 | 「已由 XXX 于 10:20 确认」 |

**第 8 条最关键**：调查失败**不能**显示成「分析已完成」。失败与不足是两个不同的状态，不能合并。

## 9. 文案规范

### 9.1 内部状态 → 用户文案

| 内部 | 展示 |
|---|---|
| `Monitoring` | 持续观察中 |
| `Investigating` | 正在进一步分析 |
| `Completed` | 分析已完成 |
| `Insufficient Evidence` | 当前证据不足 |
| `failed` / `error` | 分析未能完成 |
| `queued` / `retrying` | 正在排队分析 / 正在重新分析 |
| `acknowledged=true` | 我已了解 |

### 9.2 语气

- 说人话：不写「SpO₂ 采样异常」，写「血氧有几次没读到」
- 不制造焦虑：不写「警告！异常！」，写「需要留意」
- 不打包票：不写「一切正常，请放心」，写「目前没有发现异常」
- 不用敬语过度：称呼「您」，但不用「尊敬的用户」
